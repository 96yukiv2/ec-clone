# テスト項目マトリクス

この表は「テストコードが存在するか」を示します。**CIの合格結果を意味しません。**

| 対象 | 主なシナリオ | 検証種別 |
|---|---|---|
| 料金計算 | 割引・送料・整数円計算・境界値 | 単体 |
| 注文の業務ルール | 不正数量、冪等キー、二重決済、二重キャンセル、出荷済みキャンセル拒否 | 単体 |
| 商品カード | 名前・価格・在庫表示 | フロント単体 |
| 商品検索 | 商品一覧・検索候補・カテゴリ・フィルター・ランキング | API結合・E2E |
| 認証 | 新規登録・ログイン成功/失敗・セッション | API結合 |
| お気に入り | 登録・一覧・解除 | API結合 |
| 配送先 | 新規登録・一覧・削除 | API結合 |
| カート・注文 | 在庫引当、注文明細、再送の冪等性、Mock決済 | API結合 |
| 同時購入 | 在庫1個への同時注文は片方だけ成功 | API結合 |
| 注文キャンセル | 在庫復元・二重返却防止 | API結合 |
| Webhook | 同一イベントIDの重複通知防止 | API結合 |
| ゲスト注文 | 注文・Cookie・重複送信・Mock決済 | API結合 |
| 管理者認可 | 一般会員の操作拒否、管理者のみ商品登録 | API結合 |
| 管理画面 | 商品作成、価格変更履歴、監査ログ、売上集計 | API結合 |
| 画像管理 | 未認証ユーザーのアップロード拒否 | API結合 |
| 購入フロー | ブラウザで登録→カート→注文→Mock決済 | Playwright E2E |
| ローカル起動 | 全コンテナ起動・HTTP疎通・購入・決済 | Dockerスモーク |
| API負荷 | 商品検索への並列リクエスト、応答失敗の検出 | 軽量負荷チェック |
| 依存関係 | Controller・ServiceからDB直接アクセスを禁止 | 静的アーキテクチャチェック |

## 追加検証が必要な領域

- メール送信の失敗・再試行・重複排除
- Redis障害時のキャッシュフォールバック
- 画像ファイルの実際のマジックバイト確認
- 商品バリエーションの在庫競合
- レビューの複数人投票・不正投稿
- 大量商品投入時のN+1・インデックスの性能効果
- 消費税・送料・クーポンの複雑な組み合わせ
- 本番相当の認証・CSRF・セッション安全性

上記が未網羅なので、全機能がテスト済みとはまだ判断できません。
